# Отличия и улучшения форка OpenFlux

Данный репозиторий является развитием и официальным форком проекта **[p1neappleXpress/OpenFlux](https://github.com/p1neappleXpress/OpenFlux)**.

## Подробное описание ключевых нововведений

### 1. Сквозное AEAD-шифрование (ChaCha20-Poly1305)
- **Проблема оригинала:** оригинальный транспорт упаковывал сырые IP-пакеты напрямую в бинарные сообщения OnlyOffice. Серверы Яндекса могли выполнять глубокий анализ пакетов (DPI), логировать посещаемые сайты по SNI, перехватывать HTTP-заголовки и DNS-запросы.
- **Решение:** внедрён модуль `transport/encrypted.go`. Любой пакет перед отправкой шифруется симметричным шифром **ChaCha20-Poly1305** с 256-битным ключом. Для каждого отдельного пакета генерируется уникальный криптографический Nonce (12 байт), а целостность гарантируется 16-байтным имитовставочным тегом Poly1305. Серверы Яндекса видят исключительно случайную последовательность байт.

### 2. Полнофункциональное Android-приложение (`android/`)
- Написано с нуля на Kotlin с современным дизайном Material 3.
- **Режим VPN:** использует системный `VpnService` Android, перехватывает весь трафик устройства в виртуальный интерфейс `tun0` и маршрутизирует его через Go-стек `gVisor` (tun2socks).
- **Режим прокси:** фоновый сервис, поднимающий локальный SOCKS5 сервер (`127.0.0.1:1080`), к которому можно подключить браузер или приложения индивидуально.
- **Раздельное туннелирование (Split Tunneling):** возможность направлять через туннель только выбранные приложения (например, заблокированные сервисы) или наоборот исключать ресурсоемкие приложения (игры, стриминг).
- **Плитка быстрых настроек:** быстрое включение/отключение туннеля из панели уведомлений Android (Quick Settings Tile).
- **Мониторинг в реальном времени:** замер пинга до туннеля, отображение входящей и исходящей скорости, встроенный просмотрщик журнала событий (`LogActivity`) с возможностью экспорта логов.
- **Скрипт оптимизированной сборки:** релизная сборка с R8-обфускацией, сжатием ресурсов и подписью APK Signature Scheme v2 (размер ~17 МБ).

### 3. Multi-URL пул и отказоустойчивость
- В настройках приложения и в конфигурации сервера (`OPENFLUX_URL`) поддерживается указание нескольких ссылок на документы Яндекса через запятую или с новой строки.
- Ядро приложения циклически опрашивает пул (`atomic.Int32`) и при получении признаков блокировки (капча `showcaptcha`, HTTP 404, разрыв WebSocket-сессии) автоматически переключается на следующий рабочий документ из пула без падения VPN-соединения на телефоне.

### 4. Серверная архитектура: Docker Compose и Network Namespace
- **Docker Compose:** контейнеризация ноды выхода с правами `NET_ADMIN` и `NET_RAW`, автоматическим перехватом `RST`-пакетов и автозапуском при перезагрузке ОС.
- **Изоляция в Linux Network Namespace (`deploy/ofx-netns.sh`):** нода выхода может запускаться в изолированном пространстве имён `openflux`. Правило `iptables DROP RST` действует исключительно внутри этого пространства и ни при каких условиях не затрагивает другие приложения на сервере (Nginx, SSH, сторонние VPN-протоколы Xray, Sing-box, Outline и т.д.).
- **Systemd Watchdog:** реализация протокола `sd_notify` на чистом Go (`utils/watchdog.go`). Сервис отправляет сигналы `WATCHDOG=1` каждые 15 секунд; при зависании основного цикла systemd автоматически перезапускает ноду.

### 5. Повышение стабильности и защита от DoS
- **Защита от Decompression Bomb:** при распаковке LZ4 проверяются заголовки несжатого размера (лимит 64 КБ на пакет); попытки отправки аномально больших буферов пресекаются до аллокации памяти.
- **Предотвращение утечек горутин и сокетов:** введён атомарный счётчик поколений реконнекта `reconnectGen`. Пакеты из старых сессий не могут заблокировать или вызвать гонку в новом соединении.
- **Принудительный IPv4 (`tcp4`):** исключены многосекундные таймауты на серверах с некорректно маршрутизируемым IPv6.
### 6. Настольный Windows GUI-клиент (`desktop/`)
- **Стек:** Wails v2 + Vue 3, монолитная сборка в единый компактный исполняемый файл `OpenFlux.exe` (~18 МБ).
- **Режим Wintun (Системный VPN):** перехват всего сетевого трафика Windows (включая DNS-запросы, игры и мессенджеры) через виртуальный драйвер Wintun без потери производительности.
- **Режим System Proxy:** мгновенная активация системного прокси в реестре Windows (WinINET) без запросов прав администратора (UAC).
- **System Tray:** иконка в трее Windows со статусом подключения, контекстным меню и возможностью работы в фоновом режиме при закрытии окна.
