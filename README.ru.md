# OpenFlux — Маскированный сетевой туннель и Android-клиент

[English](README.md) | **Русский** | [**Отличия форка**](FORK.ru.md)

**OpenFlux** — система защищённой маскированной передачи сетевого TCP-трафика через легитимные облачные сервисы (в текущей конфигурации — через веб-сокет совместного редактирования Яндекс.Документов и WebRTC DataChannel мессенджера MAX). Данный репозиторий — расширенный форк [p1neappleXpress/OpenFlux](https://github.com/p1neappleXpress/OpenFlux) со сквозным шифрованием, нативным Android-приложением, пулом документов и Docker-развертыванием (подробнее: [FORK.ru.md](FORK.ru.md)).

## Основные возможности

- **Подключаемые маскирующие транспорты:**
  - **Яндекс.Документы:** эмуляция сессии совместного редактирования через Socket.IO v4 поверх WebSocket. Сетевые пакеты инкапсулируются в сообщения перемещения курсора и ревизии документа.
  - **Отказоустойчивый Multi-URL пул:** поддержка пула документов (через запятую или построчно в приложении) с мгновенным автоматическим переключением (failover) при бане, капче или недоступности документа.
  - **Мессенджер MAX:** передача трафика через сигнальный протокол и WebRTC DataChannel.
- **Сквозное AEAD-шифрование ChaCha20-Poly1305:**
  - Zero-Knowledge передача: серверы облака (Яндекс, MAX) не могут перехватить заголовки, домены (SNI), URL и DNS-запросы.
  - Индивидуальный 12-байтный случайный Nonce на каждый пакет + 16-байтный аутентификационный тег Poly1305.
  - Настройка ключа через интерфейс приложения или параметр запуска `-key`.
- **Полнофункциональное Android-приложение (`android/`):**
  - **Современный Material 3 интерфейс:** поддержка тёмной и светлой темы.
  - **Режим «Только прокси»:** компактный фоновый сервис, поднимающий локальный SOCKS5 (`127.0.0.1:1080` или `0.0.0.0:1080` для раздачи в локальную сеть).
  - **Режим VPN:** Android `VpnService`, перехватывающий весь трафик устройства в виртуальный интерфейс `tun0` через стек `tun2socks` (gVisor).
  - **Раздельное туннелирование (Split Tunneling):** белый и чёрный списки приложений.
  - **DNS-over-TCP:** автоматический перехват Android UDP DNS-запросов (53 порт) и упаковка в RFC 1035 TCP-туннель.
  - **Живой мониторинг трафика:** отображение объёма и скорости на главном экране и в шторке уведомлений Android.
  - **Защита от сбоев:** перехват паник ядра и встроенный просмотрщик логов (`LogActivity`).
- **Надёжная серверная часть для Linux (Exit Node):**
  - Маршрутизация трафика через сырые сокеты (`AF_INET RAW`).
  - Автоматическое отслеживание активных клиентских портов и таймеры очистки.
  - Принудительный IPv4 (`tcp4`), исключающий зависания соединений на dual-stack серверах.
  - **Systemd Watchdog:** аппаратный контроль зависаний процесса через протокол `sd_notify` (`WatchdogSec=30s`).
  - **Docker & Docker Compose:** готовая контейнеризация ноды выхода с сетевой изоляцией.
- **Надёжность и безопасность:**
  - Защита от утечек сокетов (`reconnectGen`), десктопный Chrome User-Agent, поддержка передачи cookie (`OPENFLUX_YCOOKIE`).
  - Устранены уязвимости отказа в обслуживании (DoS), введены лимиты на аллокацию памяти, защита от Decompression Bomb в LZ4, потокобезопасная синхронизация.

## Быстрый старт

### 1. Настройка выходной ноды (Linux VPS)

Для работы сервера OpenFlux (Exit Node) потребуется любой виртуальный сервер (Linux VPS) с правами `root` (Ubuntu 22.04/24.04, Debian 11/12, CentOS, AlmaLinux, Arch и др.).

> [!NOTE]
> **Вам НЕ нужно открывать входящие порты на сервере!**
> OpenFlux Exit Node сам устанавливает исходящее зашифрованное соединение с облачными серверами Яндекса через HTTPS/WSS (порт 443). Сервер не слушает открытые входящие порты, невидим для интернет-сканеров и цензоров, и работает даже за NAT.

#### Выберите вариант развертывания:
1. **[Вариант А: Docker Compose](#вариант-а-запуск-через-docker-compose-рекомендуемый)** — **Рекомендуется для 95% пользователей**. Разворачивается за 2 минуты, не требует установки Go, автоматически настраивает всё окружение и автозапуск при перезагрузке.
2. **[Вариант Б: Systemd в Network Namespace](#вариант-б-запуск-через-systemd-в-изолированном-network-namespace-для-серверов-с-другими-vpn)** — для серверов, где уже установлены другие VPN-сервисы (Xray, WireGuard, Sing-box) и нужна строгая сетевая изоляция.
3. **[Вариант В: Прямой запуск через терминал](#вариант-в-прямой-запуск-без-изоляции-для-быстрого-тестирования)** — для быстрой ручной проверки за 30 секунд.

---

#### Шаг 0. Подготовка Яндекс.Документов и ключа (Обязательно)

Транспорт `yandex` маскирует весь трафик под сессию совместного онлайн-редактирования документов OnlyOffice на серверах Яндекса.

1. **Создайте документ на Яндекс Диске:**
   - Перейдите на [Яндекс Диск](https://disk.yandex.ru) *(рекомендуется отдельный чистый аккаунт)*.
   - Нажмите кнопку **«Создать»** ➔ выберите **«Таблицу»** или **«Документ»** (например, `.xlsx` или `.docx`).
2. **Откройте публичный доступ:**
   - В открывшемся окне редактора нажмите желтую кнопку **«Поделиться»** в правом верхнем углу.
   - В появившемся окне обязательно переключите права с «Только просмотр» на **«Редактирование»** (доступно всем, у кого есть ссылка).
3. **Скопируйте ссылку:**
   - Нажмите **«Копировать ссылку»**. Ссылка должна иметь следующий формат:
     ```
     https://disk.yandex.ru/i/XXXXXXXXXXXXXXXX
     ```
   > [!WARNING]
   > Копируйте именно **публичную ссылку общего доступа** из кнопки «Поделиться»!  
   > **НЕ копируйте** адрес из адресной строки браузера вида `docs.yandex.ru/docs/view?...` или `disk.yandex.ru/edit/...` — это внутренняя ссылка веб-редактора, она работать не будет.

4. **(Рекомендуется) Сделайте Multi-URL пул:**
   - Повторите шаги 1–3 и создайте ещё 1–2 документа. 
   - Вы сможете указать несколько ссылок через запятую. Если один документ словит временную капчу, OpenFlux автоматически переключится на резервный документ без обрыва интернет-соединения.

5. **Сгенерируйте секретный 256-битный ключ шифрования (E2E):**
   - Выполните в терминале команду:
     ```bash
     openssl rand -hex 32
     ```
   - Вы получите строку из 64 шестнадцатеричных символов (например: `4a8f9b...3c1e`).
   - Сохраните её: этот ключ шифрования должен быть указан **одинаковым** на сервере и в приложении OpenFlux на телефоне. Никто (включая сотрудников Яндекса) не сможет прочитать ваш трафик без этого ключа.

#### Вариант А: Запуск через Docker Compose (Рекомендуемый)

Этот способ автоматически изолирует ноду выхода в контейнере, настраивает сетевой стек, применяет защиту от сбросов соединений ядром Linux (`iptables DROP RST`) и настраивает автозапуск.

##### Шаг 1. Установите Docker и Compose (если еще не установлены)
Если на вашем VPS уже стоит Docker, переходите к шагу 2. Если нет — установите его официальной командой в один клик:
```bash
curl -fsSL https://get.docker.com | sh
```

##### Шаг 2. Скачайте проект на сервер
```bash
git clone https://github.com/tatarinovs/OpenFlux.git
cd OpenFlux
```

##### Шаг 3. Создайте и настройте файл `.env`
Скопируйте пример файла конфигурации:
```bash
cp deploy/openflux.env.example .env
nano .env
```
Впишите в файл ваши данные:
```env
# Ссылка на один документ или несколько через запятую:
OPENFLUX_URL=https://disk.yandex.ru/i/ДОКУМЕНТ_1,https://disk.yandex.ru/i/ДОКУМЕНТ_2

# Секретный ключ шифрования (64 hex-символа из Шага 0):
OPENFLUX_KEY=ваш_секретный_ключ_из_шага_0

# Протокол транспорта (по умолчанию yandex):
OPENFLUX_TRANSPORT=yandex

# (Опционально) Cookie сессии Яндекса (требуются при повышенных требованиях антибот-фильтра к IP-адресу хостинга):
# OPENFLUX_YCOOKIE=yandexuid=...; Session_id=...
```
*(Для сохранения файла в редакторе `nano`: нажмите `Ctrl+O`, затем `Enter`, затем `Ctrl+X` для выхода)*.

##### Шаг 4. Соберите и запустите контейнер
```bash
docker compose up -d --build
```
Docker автоматически скачает базовый образ, скомпилирует исходники OpenFlux и запустит сервер в фоновом режиме.

##### Шаг 5. Проверьте, что сервер успешно работает
Откройте просмотр логов в реальном времени:
```bash
docker compose logs -f
```
При успешном старте вы увидите:
```text
=== OpenFlux Docker Exit Node ===
Transport: yandex
Running as EXIT NODE
[YDOCS] parsed 2 doc URLs for failover pool
[YDOCS] connectToDoc attempt 1 ...
[YDOCS] session opened, wss URL: wss://doc-api.disk.yandex.net/...
[YDOCS] connected successfully
```
*(Чтобы выйти из режима просмотра логов, нажмите `Ctrl+C`. Контейнер продолжит работать в фоне)*.

##### Управление контейнером в будущем:
```bash
# Посмотреть статус:
docker compose ps

# Перезапустить сервис:
docker compose restart

# Остановить сервис:
docker compose down

# Обновить на новую версию:
git pull
docker compose up -d --build
```

#### Вариант Б: Запуск через Systemd в изолированном Network Namespace (Для серверов с другими VPN)

Exit Node использует сырые сокеты (`AF_INET RAW`), из-за чего ядро Linux пытается сбрасывать входящие ответы пакетами `TCP RST`. Правило `iptables -A OUTPUT -p tcp --tcp-flags RST RST -j DROP` решает эту проблему. 

Чтобы это правило действовало **только на OpenFlux** и не мешало соседним службам на сервере (Nginx, SSH, Docker, Xray, VLESS), нода изолируется в пространстве имён `openflux`:

1. **Сборка бинарника под Linux:**
   ```bash
   go build -ldflags="-s -w" -o universal-bypass-tool .
   sudo mkdir -p /opt/openflux && sudo cp universal-bypass-tool /opt/openflux/
   ```

2. **Установка скрипта изоляции и сервисов systemd:**
   ```bash
   sudo install -m 755 deploy/ofx-netns.sh /usr/local/sbin/
   sudo install -m 644 deploy/openflux-netns.service deploy/openflux.service /etc/systemd/system/
   ```

3. **Настройка конфигурации окружения:**
   ```bash
   sudo cp deploy/openflux.env.example /etc/openflux.env
   sudo nano /etc/openflux.env
   ```
   Укажите ссылки `OPENFLUX_URL` и ключ `OPENFLUX_KEY`.

4. **Активация и запуск служб:**
   ```bash
   sudo systemctl daemon-reload
   sudo systemctl enable --now openflux-netns.service openflux.service
   ```

5. **Проверка статуса и соединений:**
   ```bash
   # Статус службы (должен быть active (running) и активен Watchdog):
   sudo systemctl status openflux.service

   # Проверка установленных соединений внутри пространства netns:
   sudo ip netns exec openflux ss -tnp

   # Убедиться, что на основном хосте нет глобального DROP RST (вывод чистый):
   sudo iptables -L OUTPUT -n | grep -i rst

   # Просмотр логов в реальном времени:
   sudo journalctl -u openflux.service -f
   ```

#### Вариант В: Прямой запуск без изоляции (если сервер выделен исключительно под OpenFlux)

Если на сервере нет других сервисов, можно запустить бинарник напрямую:
```bash
sudo iptables -I OUTPUT 1 -p tcp --tcp-flags RST RST -j DROP
sudo ./universal-bypass-tool -exit-node \
  -transport yandex \
  -url "https://disk.yandex.ru/i/ВАШ_КЛЮЧ_ДОКУМЕНТА" \
  -key "ВАШ_КЛЮЧ_ШИФРОВАНИЯ" \
  -debug
```

### 2. Сборка Android-клиента

#### Автоматическая сборка Release APK в 1 клик (Windows):
Запустите [build_release.bat](build_release.bat):
```cmd
build_release.bat
```
Скрипт автоматически:
1. Скомпилирует `libopenflux.so` со всеми оптимизациями (`-trimpath`, `-ldflags="-s -w"`, CGO `-O3`).
2. Запустит Gradle `assembleRelease` с **R8-обфускацией/минификацией** и **Resource Shrinking**.
3. Подпишет APK схемой **APK Signature Scheme v2**.
4. Сохранит готовый к установке пакет в папку `releases/OpenFlux-release.apk` (размер ~17 МБ).

#### Ручная сборка через PowerShell:
```powershell
# Сборка Go-библиотеки под arm64-v8a
$env:GOOS = "android"; $env:GOARCH = "arm64"; $env:CGO_ENABLED = "1"
$env:CC = "C:\Users\<user>\AppData\Local\Android\Sdk\ndk\<версия>\toolchains\llvm\prebuilt\windows-x86_64\bin\aarch64-linux-android24-clang.cmd"
go build -trimpath -buildmode=c-shared -ldflags="-s -w -checklinkname=0" -o android/app/src/main/jniLibs/arm64-v8a/libopenflux.so ./mobile

# Сборка APK
cd android
.\gradlew.bat assembleRelease
```

### 3. Десктопный клиент (CLI)

Для маршрутизации трафика браузера или системы через туннель на ПК:

```bash
./universal-bypass-tool -client \
  -transport yandex \
  -url "https://disk.yandex.ru/i/ВАШ_КЛЮЧ_ДОКУМЕНТА" \
  -socks5 127.0.0.1:1080 \
  -key "ВАШ_КЛЮЧ_ШИФРОВАНИЯ" \
  -debug
```
После запуска укажите SOCKS5 прокси `127.0.0.1:1080` в настройках вашей системы или браузера.

## Безопасность и приватность

1. **Защита от сервера-посредника:** Облачный сервис видит лишь base64-строки курсорных сообщений с высокой энтропией (криптографический белый шум). Никакие сетевые заголовки, домены и данные не утекают в сервис Яндекса или MAX.
2. **Защита от Zip-Bomb:** Распаковка LZ4 ограничена константой `MaxDecompressedSize = 10 MB` на фрейм, предотвращая атаки на исчерпание оперативной памяти.
3. **Безопасная архитектура:** Защита от переполнения буферов, перехват паник во всех горутинах и строгий контроль границ пакетов.
